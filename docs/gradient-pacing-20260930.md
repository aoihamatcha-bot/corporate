2026-09-30。Implementation。開始HEAD `a2b6ab2fe7dbce7d765e0ca0dab4ee34c01a5436`、branch `feat/corporate-readability-20260922`。前回の候補に対する「速すぎる」「以前の淡いグラデーションではない」というOwnerの指摘を受けた修正。以前の検証PASSを見た目の採用とは扱わない。

## 実装判断

- 本文の帯は、全体に強いease-outをかけていたため、最も見える区間が冒頭へ圧縮されていた。秒数だけを伸ばさず、広がる・留まる・消えるの3区間に分けた。メニューのCSSも同じ段階構成に揃える。
- 見出し1800–1933ms、本文1800–1933ms、ラベル1600–1733ms、操作名1500–1633ms。最初の40%で広がり、65%まで留まり、最後の35%で消える。複数行は従来どおり最大260msの差を付ける。
- 文字の出現は160msから480msへ。帯が消えた後に約1.0–1.34秒色を保持し、約1.3–1.9秒で通常色へ戻る。従来の400–600ms保持は今回の「遅くしてほしい」という依頼で更新する。
- 見出しの帯に使われていた鮮やかな画像用の色を外し、既存8系統（Sky / Mint / Apricot / Iris / Lagoon / Rose / Honey / Twilight）の淡い色へ統一する。色値は `f4ce8c8` 以降の既存値をそのまま使用。本文・メニュー・数字も同じ定義を参照する。
- 文字自体は同系色の濃いトーンを保ち、彩度を45%へ抑えて蛍光色のような発色を和らげる。淡い文字で読めなくなることを避けるため、文字用の濃度と背景の淡い色は分ける。黒へ戻る流れと全テキストへの適用を維持する。暗いフッターは明るい文字へ戻る。
- 背景の静止面・セクション配色・画像演出・原稿・openingの手書きや着地・公開条件は変更しない。Reduced Motion、Forced Colors、JavaScript無効、API失敗、画面サイズ変更時のフォールバックを維持。

## 検証の読み方

自然再生を録画し、代表本文の帯の濃さをrequestAnimationFrameで採取する。修正前はopacity > 0.45の区間がPC約22ms / スマホ約83ms、修正候補は約1133ms / 約1201ms。速度と最大opacityの両方を変更しているため、これを速度だけの改善率とは解釈しない。固定時刻へ飛ばした画像ではなく、通常の再生中に取得した画像も保存する。
