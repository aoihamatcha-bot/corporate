# Whateverの公開実装調査 — 2026-09-08

前回の [視覚観察](reference-analysis.md) を補う追記。前回の記録は変更していない。今回は [参考ページ](https://whatever.co/ja/) の公開CSS・配信JavaScript・実ブラウザでの `Element.animate()` 呼び出しを確認した。添付スクリーンショットは表現上の参考として扱い、以下の技術的な事実とは区別する。

## 確認できた構造

| 対象 | 公開実装と実行時に確認した内容 |
|---|---|
| 描画 | Next.js / Reactの配信コード。調査した文字・画像・メニューの効果はDOM、CSS、Web Animations APIで動作する |
| 色 | 9つの基準色から異なる2色を選ぶ。4つの固定画像を切り替える方式ではない。毎回同じ2色になる可能性もある |
| グラデーション | Oklab補間の線形グラデーションとノイズ画像を重ねる |
| 文字 | 元の文字、横切る色の帯、文字に色を重ねる面が別々に存在する。白地では `lighten`、白文字用には `multiply` を使う |
| 時間 | 帯の基準時間250ms、文字の色抜け1250ms。通常要素には0〜500msのランダムな開始待ちがある。時間は公開コードと実行時の引数で確認した値 |
| 表示開始 | 要素ごとのIntersectionObserver。初期表示領域も別途確認し、一度表示した対象の監視を解除する |
| メニュー | 全画面背景と各項目に個別の効果を適用する。背景は待ち時間なし、項目は別々の色と開始待ち時間を持つ |
| 画像 | 初回用の色面と帯、ホバー用の色面が分離される。ホバー面は `screen` 合成、入り・抜けは125ms |

ブラウザで実際の作品画像へ6回入り直すと6種類の2色組み合わせが得られ、いずれも `screen` 合成だった。対象はブラウザの公開画面に読み込まれた画像であり、MYSTENAには転載していない。

対象の効果をライブラリの名称から推測していない。調査範囲の動作にGSAP、Canvas、WebGLは必要なかったが、これを根拠にサイト全体の依存ライブラリの不在までは断定しない。

## MYSTENAでの実装判断

- 白い本文領域は、色の帯 → グラデーション文字 → 黒い本文という順にする。暗いヒーローは背景に合わせ、最後は白文字へ戻す。
- 元の文章を常に初期HTMLに残し、実際の折り返し行をRangeで測る。行ごとの帯と装飾用の文字を重ねる。装飾は支援技術の読み上げ対象に含めない。
- 背景・文字・画像の色は別に管理する。MYSTENAのSky / Mint / Apricot / Irisの4系統に、明るい面用と濃い文字用の色を持たせた。
- 画像はページ表示時の先頭配色を変え、再ホバーまたはキーボードフォーカスで4系統を一巡する。画像自体は支給されたAfterglow / Daylightの抽象ビジュアルで、実績や商品を創作しない。
- メニューは2枚の背景色面と、各英字の色・帯を独立させる。リンクの当たり判定は動かさず、フォーカス項目の帯を解除する。
- アニメーション用の追加ライブラリは導入しない。MYSTENAの読みやすさに合わせ、帯620ms、文字1600ms、画像1500ms、画像への再操作280msへ調整した。参考サイトの値と同一ではない。
- 画面外・ページ非表示・幅変更・停止設定・API失敗時は装飾を除去する。本文の初回進入をセクション全体の進入で消費しない。
